# Design decisions and deviations

Changes to the design in `PLAN.md` / `BUILD.md`, newest last. Format: date, decision, why.

- 2026-10-06: The web UI is embedded from `web/dist` when built, else from `web/placeholder` (picked by `crates/hue-jack/build.rs`), instead of committing a placeholder `web/dist/index.html`. Why: Vite empties `dist/` on every build, so a committed placeholder would show as modified after every UI build. `web/dist` is gitignored.
- 2026-10-06: shairport-sync 5.5.2 and nqptp 1.2.8 are built from source in the image. Fedora 44's `shairport-sync` 4.3.7 is built without AirPlay 2 (no libplist/libsodium/libav) and without MPRIS (no gio). The 5.x configure flags are `--with-pipewire`/`--with-pulseaudio` (BUILD.md's `--with-pw` is the 4.x name) and the backend is `output_backend = "pipewire"`. Fedora's `ffmpeg-free` includes the native AAC decoder AirPlay 2 needs, so RPM Fusion isn't required.
- 2026-10-06: The installer user and SSH key are created by kickstart commands (`user`, `sshkey`, `rootpw --lock`) in `os/bib/config.toml`, not `[customizations.user]`. Why: bootc-image-builder doesn't support `[customizations.user]` together with a custom kickstart.
- 2026-10-06: All hue-jack user units carry `ConditionUser=huejack`, and a drop-in resets bluez's `mpris-proxy.service` `ConditionUser=!@system`. Why: `systemctl --global enable` enables them for every user (an SSH login as alex would start a second hue-jack), and huejack is a sysusers system user, which `!@system` would skip.
- 2026-10-06: `nqptp.service` keeps upstream's `DynamicUser=yes` + `CAP_NET_BIND_SERVICE` rather than running as root. Why: upstream's recommended unit; it only needs ports 319/320 and a world-accessible shared-memory segment.
- 2026-10-06: The image adds `iwlbluetooth-firmware` (the NUC's Intel 8260 Bluetooth needs its `ibt-*` firmware; the bootc base doesn't include it) and disables WirePlumber's default-node state (`hooks.default-nodes.state`), so `hue-jack-in` is the default sink after every boot.
